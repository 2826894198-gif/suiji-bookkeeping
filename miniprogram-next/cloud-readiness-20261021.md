## 固定配置与数据保护

- AppID：`YOUR_WECHAT_APPID`。不得为更新新建 AppID。
- 账本键：`pearl_ledger_v1`；内部 schema 2，兼容本应用 v1 备份，迁移前备份。
- 同步键：`pearl_cloud_sync_v1`。固定环境、微信身份摘要、云端版本、已核对摘要及待提交操作 ID 在更新时保留。
- 版本键：`pearl_app_release_v1`。每次版本变更前创建本机升级恢复点，不清理数据。
- 单次云同步载荷上限 8 MB；超限明确报错，不截断账本。每次上传包含完整累计账本，云端最近 30 个版本是恢复窗口，不是只保留 30 笔记录。
- 本机恢复点可能随微信数据清理、卸载、换机丢失；独立 JSON 导出应另存到用户自选位置。

## 后续部署维护与验收步骤

1. 更新时继续使用上述已核对的环境、AppID 和集合，不新建一套数据空间。
2. 集合权限保持仅管理端读写。`cloudfunctions/database.rules.json` 仅为配置说明，不会自动生效；后续如调整权限需实际读回核对。
3. 在项目目录执行 `node scripts/prepare-cloud.js --check` 及 `node --test tests/*.test.js`。需要更新共享业务模型时先运行不带 `--check` 的脚本。
4. 云函数更新优先使用官方受支持的部署入口，检查实际部署结果而非仅看退出码。服务端仅接受指定 AppID 的微信上下文，不信任客户端身份字段；保持锁定依赖和 3 秒配置一致。
5. 客户端已配置该环境。预览、体验与后续更新不按 `envVersion` 切换环境。先完成真实微信上下文的连接、身份隔离和读写，再宣告可用。
6. 使用明确的合成测试账本验证首次上传、读回、断网补传、两端冲突、历史恢复与重启保留。恢复前数据必须能从本机恢复点读回。
7. 上传开发版本并设为个人体验版；不提审、不公开发布。微信公众平台页面受浏览器站点策略限制时，交由用户本人完成必要的体验版设置，不绕过策略。
